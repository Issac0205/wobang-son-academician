# v1.7.0 — 亲带同时数量上限改为「按头衔」

## 这一版新增

「老板亲带」的**同时数量上限**不再由精力派生（旧实现 `Math.max(1, Math.floor(精力上限 / 2))`，
健康好时能带到 6–10 个），改为**由头衔决定**：`src/data/ranks.js` 每个 rank 新增 `playerLeadCap`。

| 档 | 头衔 | 同时最多亲带 |
| --- | --- | --- |
| 1 | 副研究员 | 1 |
| 2 | 研究员 | 2 |
| 3 | 副教授 | 2 |
| 4 | 教授 | 3 |
| 5 | 优青 / 万人 | 3 |
| 6 | 杰青 / 长江（单有） | 4 |
| 7 | 杰青 + 长江（兼有） | 4 |
| 8 | 院士 | 4 |

- **亲带本身的代价一行未改**（本轮只改「同时数量上限」）：项目推进 ×0.85（`PLAYER_LEAD_MUL`）、
  每月多 1 点精力（`PLAYER_LEAD_ENERGY_COST`）、该项目论文一作全部归玩家（t24）。
- 上限值**只住 src/data**：core 走 `rankOf(state.player.rankIndex).playerLeadCap`，
  `scripts/check.mjs` 的 core 常量白名单照旧通过（core 里没有上限的字面量）。
- **旧档超限**（例如副教授挂着 4 个亲带）：**不追溯取消**——项目照旧有效、仍显示「亲带中」，
  引擎没有任何自动撤销路径；但**禁止再新增**——toggle 到超限一律拒绝 + 中文 toast
  （写明「当前头衔上限 / 已带数量」），项目页另给一条**可关掉**的提示。
  **取消亲带永远允许**（不受上限约束，超限档也一样）。
- 机器人（`src/systems/bots.js`）不再用精力派生上限，与引擎同一把尺子（`cfg.leadMax` 只作为「自愿少带几个」的更低自限）。
- 百科「一作三途径 → 亲带」词条自动带上「同时最多 N 个（随头衔提升；你当前是「×××」）」，
  由 `selectWiki(state)` 组装 → `vm.consts.wiki` → `src/ui/views/wiki.js` 只排版（该文件仍无数字字符）；
  N 取**玩家当前头衔**的真实值，UI 不写死。
