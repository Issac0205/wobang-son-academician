> 本文件由项目主理人依照用户原始需求整理，逐条保留原意，是团队**唯一权威需求来源**。

## 0. 项目一句话

开发一款比较简单的**网页小游戏**，题目是「我帮儿子评院士」。
这是一款**诙谐幽默**的养成 / 经营游戏。玩家扮演**课题组的大老板**。
初始拥有 200 万经费，可以购买试剂、发工资、购买仪器、发福利、自己享乐。
终极目标：把「马小程」从副研究员一路刷成**院士**。

## 2. 课题组参数

### 2.1 经费
- 可以用于购买大多数资源。
- 来源主要有三类：**学校投资**（根据头衔）、**国家投资**（根据承接的项目）、**横向经费**（与企业合作）。

### 2.2 学生容量
- 硕士生容量：分为**上限**和**当前人数**，随头衔增加上限，**初始上限为 4**；三年毕业。
- 博士生容量：分为**上限**和**当前人数**，随头衔增加上限，**初始上限为 1**；五年毕业。

### 2.3 仪器设备
每台仪器提供不同的科研进度加成，初始持有量各不相同：

| 仪器 | 加成 | 初始数量 |
|---|---|---|
| 离心机 | 小幅增加科研进度 | 1 |
| 摇床 | 小幅增加科研进度 | 1 |
| 液相 | 大幅增加科研进度 | 1 |
| 质谱 | 大幅增加科研进度 | 0 |
| 超净台 | 小幅增加科研进度 | 2 |
| 酶标仪 | 大幅增加科研进度 | 0 |
| 气相 | 大幅增加科研进度 | 0 |
| 水浴锅 | 小幅增加科研进度 | 1 |

### 2.4 耗材资金与消耗模式
- **耗材资金**：专门用于购买耗材的资金池。
- 三种消耗模式：
  1. **随意挥霍**：成员会一定程度浪费耗材，但科研效率提高、幸福度下降变慢。
  2. **正常消耗**：不影响科研效率和幸福度。
  3. **收紧裤腰**：大于 10ml 的离心管必须清洗回收；科研效率下降、幸福度下降加快。

### 2.5 目前承接项目（显示层要求）
- 显示当前承接的**国家项目**和**公司项目**。
- 每个项目都有**规定完成时间**；完成后**发表论文获得影响因子和尾款**。
- 每个项目都显示**当前研究进度**；越难的项目进度中**难点越多**。
- 对难点有三种处理方式：
  1. **多人攻坚**：影响其他项目进度。
  2. **造假蒙混**：降低你的诚信值，可能会被举报。
  3. **单人猛干**：消耗更多财力，降低该研究生的幸福度。

## 3. 个人参数（玩家角色）

- **姓名**：初始姓名「马小程」，玩家可自行修改。
- **头衔**：副研究员 > 研究员 > 副教授 > 教授。
  上限梯度：**院士 > 杰青/长江兼有 > 杰青/长江单有 > 万人/优青 > 其他教授**。
  初始头衔为**副研究员**。
- **总影响因子**：课题组投稿期刊获得的影响因子总和。
  达到一定数字、并且满足 SCI 一作数量以后，头衔晋升。
- **SCI 一作数量**：分为**一区数、二区数、三区数、四区数、正刊数**。
  - 每个课题结题后，对应项目的负责人可以获得该论文的一作。
  - **可以从学生那里抢夺一作**：大幅减少诚信值、减少对应学生幸福度。
  - **购买一作**：消耗经费获取；对幸福度减少比较少，诚信值减少也比较少；越厉害的文章购买需要越多资金。
  - 初始为**一篇一区一作**，其他为零。
- **诚信值**：初始为 100。完成项目可以提高；不诚信行为会减少。**降低为零时触发被举报的坏结局**。
- **精力值**：每月更新，是用来完成一些行动的点数。
- **健康值**：影响精力值上限。
- **可采取的行动**（4 种）：
  1. 与学生交流课题（增加对应课题的进度）
  2. 开组会（增加全体课题进度）
  3. 锻炼与享乐（增加健康值）
  4. 去团建（增加全体幸福值）

## 4. 研究生参数
- 每个研究生都有自己的**名字**，需要建立一个**很自然的随机命名系统**，
  「不要生成的名字千篇一律，很没有代入感」。
- 每个学生有**在读年份**、**毕业进度**（论文完成进度；幸福度太低会降低）。
- 达到毕业年份后可以**延毕该生一年**：大幅降低幸福度，但该生**不占用招生名额**，可以多招一个学生。
- **幸福度**：初始 60。降到 0 时该生会**转入别的课题组**（导致他负责的项目进度减少 60%）；
  也有小概率 **0.5% 会自杀**，直接减少你 **50 诚信值**。
- **工资水平**：分为**高 / 中 / 低 / 无**四档。
  高工资增加幸福度；低工资降低幸福度；中工资不变动；无工资大幅降低幸福度。
- **科研能力**：每个学生初始自带，影响对课题研究的进度。

## 5. 课题市场参数
- 市场上有很多项目（**国家的**和**企业的**）。
- 每个项目有**承接的最低要求**（例如必须有液相 / 酶标仪 / 质谱等），越高端的项目要求越高。
- 越好的项目给的钱越多。
- 每个项目**至少要有一个人负责**，也可以分配给多人。
- 承接时**直接获得一部分定金**，完成时获得**尾款**。

## 6. 人才市场参数
- 可以看到今年可以招收的学生。
- **游戏刚开始时**可以看见；并且**每年 6–12 月开放人才市场**。
- **6–10 月**刷新**保研生**：科研能力普遍更高，需要更多头衔和影响因子才能招到，可以花钱招收。
- **10–12 月**刷新**考研生**：有概率刷新高科研能力的，但平均科研水平低于保研生。
- **天赋越高越需要更高工资**。

## 7. 数值要求

→ 数值必须成体系、可解释、可调；集中在数据文件中，不要散落在逻辑里。

## 8. 技术约定（主理人补充，非用户原文）
- 纯前端、零构建依赖：ES Module 源码 + 开发用 node 静态服务器 + 发布用单文件 HTML 打包。
- 直接双击单文件 HTML 即可游玩；存档用 localStorage。
- 参考工作区内既有同类项目 `D:/harness/xiuxian-family/` 的工程惯例：
  `src/core`（引擎/状态/存档/公式）、`src/data`（纯数据表）、`src/ui`（视图）、`src/styles`（CSS）、
  `scripts/*.mjs`（check / simulate / ui-smoke / build-single）、`server.mjs`、`package.json`。
- 所有可调数值集中在 `src/data/`，逻辑只读数据，禁止硬编码魔法数字。
