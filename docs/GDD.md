## 0. 阅读说明与约定

- **单位**：货币统一用「**万元**」（简写 万）；影响因子用「**IF**」（点）；时间用「**月**」。
- **来源标记**：`[SPEC]` = SPEC 硬性值，不得改动；`[研究]` = RESEARCH.md 有真实资料的量级锚点；`[策划]` = 策划推断的可调值。
- **名词**：玩家角色「马小程」（可改名）、学生、课题组、头衔、项目、难点。
- **五项一作档位**：一区 / 二区 / 三区 / 四区 / 正刊（正刊 = Nature / Science / Cell 级别的国际顶级正刊）。
- **公式一律是纯函数**，输入输出都是数字；随机一律显式写 `U(a,b)`（均匀分布）或 `N(μ,σ)`（正态）。

## 1. 核心循环与一局节奏

### 1.1 一局目标与时长

| 项 | 值 | 说明 |
|---|---|---|
| 起始状态 | 头衔「副研究员」，33 岁 0 月 | `[SPEC]` 初始头衔；年龄为 `[策划]` |
| 通关条件 | 头衔推进到第 8 级「院士」 | `[SPEC]` 终极目标 |
| 目标通关月数 | 中位 **182 个月**（15 年 2 个月），典型区间 **171–189 个月** | `[策划]`，见 §11 数值自检 |
| 熟手通关月数 | 130–150 个月 | 精准分配 + 不反复试错 |
| 每月决策耗时预算 | 17–22 秒 | 界面一次点击 ≤ 3 秒反馈 |
| 一局实际时长 | **51 分钟**（中位）／熟手 35–45 分钟 | 182 × 17s ≈ 51 min，落在主理人建议的 30–60 分钟内 |
| 硬性上限 | 第 384 个月（65 岁）未到院士 → 退休结局 | 见 §9 |

> 设计意图：把现实中「副高→正高→帽子→院士」约 25–30 年的职业进程压缩到 15 年左右，是 SPEC「线性阶梯」简化的必然结果；时间压力靠「黄金年龄窗口」（§3.3）而非硬拦截实现。

### 1.2 月度循环（五阶段，严格按序）

每一回合 = 游戏内 **1 个月**。玩家点「下一个月」推进，引擎按下列顺序结算：

```
①  月初结算  INCOME  —— 学校投资到账、项目定金入账（若有）、上月结转
②  行动阶段  ACTION  —— 消耗精力执行 4 种行动（任意顺序、可重复，精力耗尽为止）
③  市场阶段  MARKET  —— 仪器采购 / 人才市场 / 承接项目 / 购买一作 / 财务划拨
④  事件阶段  EVENT   —— 难点触发、随机事件（每月 1–2 条）、学生个体事件
⑤  月末结算  SETTLE  —— 项目进度 → 学生幸福度与毕业进度 → 诚信变更 → 晋升判定 → 结局判定 → 自动存档
```

阶段锁定规则：进入 ③ 之后不能再执行 ② 的行动；进入 ⑤ 之后本月不可操作（避免「看到结算结果再改行动」的读档套利）。

### 1.3 年龄与时间轴

- 年龄以「年龄 + 月龄」呈现：第 m 个月的年龄 = `33 岁 + (m−1) 月`。
- 学生「在读月数」与全局月数同步递增；玩家年龄**不影响**任何产出系数，只影响 §3.3 的黄金窗口与 §3.4 的院士推荐难度。
- 第 384 个月（65 岁）触发退休结局（§9）。

### 1.4 界面信息架构（供 UI 实现参考）

五个标签页：**课题组**（玩家资源 + 学生列表）/ **项目**（承接中项目、进度条、难点）/ **市场**（项目、仪器、人才）/ **行动**（4 种行动 + 精力条）/ **纪事**（事件文案流）。所有数值变化都在「纪事」里留下一句可读的吐槽文案（借鉴 QualityCampus「树洞链」思路）。

### 2.2 经费：三个来源

**① 学校投资（按头衔，每月发放）** — `[SPEC]` 要求「根据头衔」

```
每月到账 = SCHOOL_FUND_YEAR[rankIndex] / 12
```

| rankIndex | 1 副研究员 | 2 研究员 | 3 副教授 | 4 教授 | 5 优青/万人 | 6 杰青单有 | 7 兼有 | 8 院士 |
|---|---|---|---|---|---|---|---|---|
| 年投资（万） | 72 | 120 | 180 | 240 | 320 | 420 | 560 | 760 |
| 月到账（万） | 6.0 | 10.0 | 15.0 | 20.0 | 26.7 | 35.0 | 46.7 | 63.3 |

> `[研究]` 锚点：学校投资无公开统一标准 [C]；本表按「副研究员年投资 ≈ 一个青年基金（30 万）× 2.4」标定，并随头衔近似翻倍增长。

**② 国家投资（项目定金 + 尾款）** — `[SPEC]`

```
承接时入账  定金 = 项目总额 × DEPOSIT_RATE[类别]      国家 0.30 / 企业 0.40
结题时入账  尾款 = 项目总额 × (1 − DEPOSIT_RATE)
逾期结题    尾款 × 0.80（UNDERDUE_TAIL_PENALTY）
每个未解决难点  尾款再 × 0.80（PER_HARDPOINT_TAIL_PENALTY）
```

**③ 横向经费（企业项目）** — `[SPEC]`「与企业合作」：企业项目即横向项目，见 §5 表。

### 2.3 耗材资金：划拨与消耗

`[SPEC]` 要求「耗材资金：专门用于购买耗材的资金池」。规则：

```
承接项目时  耗材资金 += 定金 × DEPOSIT_TO_CONSUMABLE(0.40)
随时可操作  经费 → 耗材资金 1:1 划拨（TRANSFER_RATE = 1.0，无手续费、无损失）
每月消耗    耗材资金 −= Σ(每个在研项目的 CONSUMABLE_PER_MONTH × 消耗模式系数)
```

- 消耗模式系数 `CONSUME_MODE_COEF`：**随意挥霍 1.60** / **正常消耗 1.00** / **收紧裤腰 0.60** — `[SPEC]` 三种模式。
- **单位口径（t8 修复）**：耗材资金与经费同为本位「万元」，`CONSUMABLE_PRICE_PER_UNIT = 1` ⇒ **1 单位 = 1 万元**。UI 在「课题组 · 耗材库」常驻标注这条换算，顶栏「耗材资金」悬停也能看到；界面里出现的「单位」一律按此换算读作万元。
- **耗材资金 = 0 时**：所有在研项目本月进度 ×0，并触发「断粮」事件（全体学生幸福度 −5）。这是「把经费全砸在仪器上」的惩罚。

### 2.4 精力

```
精力上限 energyMax = 2 + floor(health / 10)        // health 80 → 10，100 → 12，0 → 2
健康 ≤ 30 时      energyMax = floor(energyMax / 2)  // 体检报告：精力腰斩
每月月初          energy = energyMax                // 不结转（ENERGY_CARRYOVER = 0）
玩家亲自负责项目   每月额外 −1 精力 / 个玩家负责的项目
```

### 2.7 总影响因子

```
每篇论文结题时结算
IF_i = JOURNAL_IF_BASE[tier] × U(0.85, 1.15)      // 保留 1 位小数
tier ∈ {正刊 45.0, 一区 10.0, 二区 5.5, 三区 3.2, 四区 1.3}
totalIF += IF_i（所有论文，无论一作归属）
```

> **两套门槛的分工**：**总影响因子统计全部论文**（含学生一作的）；**晋升门槛里的「一区/二区/…一作数」只统计玩家为一作的论文**（§3、§5.6）。
> **v2（t24 定稿）**：学生一作的论文**不进玩家的一作台账**（既不算 `firstQ1`…`firstTop`，也不算「玩家的论文」），它只计入总影响因子与课题组论文数；玩家的一作只能来自「亲自带项目 / 抢 / 买」——三条途径与代价见 §2.8、新手引导见 §2.9。
> `[研究]` 免责：一区 10 / 二区 5.5 / 三区 3.2 / 四区 1.3 为跨学科 IF 量级估算 [C]（生物医学/材料一区常见 8–10，化学/工程 6–10，二区 4–8，三区 2–5，四区 <2）；现实中「破四唯」明确反对以 IF 作标签 [A]，本作按游戏化夸张处理。

### 2.8 SCI 一作（五档）

- **一作归属规则（v2，t24 定稿）**：项目结题时，论文一作归**该项目负责人**。负责人在承接项目后随时可切换（「我亲自带 / 取消亲带」，见 §5.1），一名玩家可同时亲带多个项目（上限见 §2.4 精力）。
  - **负责人 = 玩家（亲带）**：该项目**全部**论文的一作归玩家 —— 每篇都 +1 到玩家的一作台账（分档计入 `firstQ1`…`firstTop`）。代价：**该项目推进速度 ×0.85**，且玩家**每月每个亲带项目多消耗 1 点精力**（机制说明见 §5.3）。
  - **负责人 = 学生**：一作归该生，玩家得**通讯作者**。**关键（v2）**：这类论文**不计入玩家的一作台账**——它不是「玩家的论文」。它仍然计入：① 总影响因子 `totalIF`（§2.7）；② 课题组的论文数（月报里的「全组论文」）。该生幸福度 +2 / 月。
  - 也就是说：**晋升门槛只看「你本人的一作」，全组论文再多也不会替你升职**；而 `totalIF` 门槛看的是**全部**论文。两套口径的分工见 §2.7。
- **抢一作**：结题结算界面可对**每一篇**学生一作的论文点「抢一作」：诚信 −8、该生幸福度 −30、该生进入 6 个月的「心结」状态（每月额外 −2 幸福度）；该篇转为玩家一作，**恰好 +1 篇**，不会再重复计入总影响因子（IF 在结题时就已入账）。一篇只能抢一次、一名学生一个月只能被抢一篇。
- **购买一作**：市场中可购买任意档位的一作，诚信 −4，该篇**恰好 +1 篇**，**没有任何项目/学生产出**（相当于「买一篇挂名」）。越厉害的文章越贵 — `[SPEC]`。

| 档位 | 购买价（万） | 诚信代价 |
|---|---|---|
| 四区 | 2 | −4 |
| 三区 | 5 | −4 |
| 二区 | 12 | −4 |
| 一区 | 25 | −4 |
| 正刊 | 120 | −4 |

> **与 SPEC 的一处差额（登记，未落表）**：SPEC 写「购买一作：消耗经费、**诚信与幸福减少较少**」；当前实现只扣经费与诚信，**学生幸福代价为 0**。差额与建议值（该篇原一作学生 −6，或全组 −2）登记在 BALANCE §18.5，等待主理人裁定后落表。

### 2.9 给玩家的必备引导：一作从哪来（不做会在副研究员卡死）

> 本节用**玩家语言**写，可直接作为新手引导 / 教学提示的文案来源（游戏内文案的落地建议见 `docs/DEV.md` §7.4）。

**一句话**：**能不能升职，看的是「你自己的 SCI 一作」有多少篇 —— 不是全组发了多少论文。**

每一级晋升都会要求你本人持有若干篇「一区一作 / 二区一作 / 正刊一作」；而你**开局只有 1 篇一区一作**（那是你当年评副研究员时的那篇）。从「研究员」开始就要 2 篇一区一作，所以：**你必须主动去弄一作，否则会一直停在副研究员**（这是设计好的硬规则，不是 bug）。

拿到一作只有三条路：

| # | 途径 | 拿到什么 | 你要付的代价 |
|---|---|---|---|
| ① | **亲自带项目**（项目卡片上的「我亲自带」） | 该项目**全部**论文的一作都归你 | 该项目学生的科研进度**变慢 15%**；**每个亲带项目每月多花 1 点精力** |
| ② | **抢学生的一作**（结题后按篇点「抢他一作」） | 那一篇的一作归你 | **诚信 −8**；**该生幸福度 −30**，并记恨 6 个月（每月再 −2 幸福度） |
| ③ | **买一作**（课题组的「一作交易台」） | 那一篇的一作归你 | **花钱**（四区 2 万 … 正刊 120 万）+ **诚信 −4**；没有真实产出 |

**新手建议的取用顺序**：

1. **前期（副研究员 → 研究员 → 副教授）**：能亲带就亲带。亲带一本科级或面上项目，结题时那一批论文全部记在你名下，通常一次就能补齐两三级的一作缺口。**精力有限时可以只亲带「出稿多、档位高」的那个本子**（比如重点、优青、杰青级项目，一区论文占比高）。
2. **中期遇到「差一篇正刊」**：优先去做**重大项目**（它们的论文槽位里才有正刊档），或者直接**买**——正刊一口价最贵，但后期经费充裕时它是最快的补位手段。
3. **「抢」是应急手段，不是常规手段**：一次 −8 诚信、−30 学生幸福度，学生幸福度归零会转组（带走该项目 60% 的进度）甚至触发极端事件；诚信归零直接坏结局。用它之前先看诚信余量。
4. **三件事都别做的后果**：384 个月过去，你会带着几千点总影响因子、几十个结题项目，**停在副研究员退休**——因为那些论文的一作全是学生，一篇也没记在你名下。

## 3. 职称晋升阶梯（副研究员 → 院士）

### 3.1 八级阶梯总表

| # | 头衔 | 总 IF | 一区一作 | 二区一作 | 正刊一作 | 项目要求 | 硕士上限 | 博士上限 | 学校年投资(万) | 可承接最高等级 | 同时承接上限 | 黄金年龄 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | **副研究员**（初始） | 0 | 1（初始持有，非门槛） | 0 | 0 | — | **4** | **1** | 72 | T2 | 2 | — |

### 3.2 晋升判定顺序

每次月末结算按顺序检查**所有**条件，全部满足才晋升（一次结算最多升 1 级）：

```
canPromoteTo(r) =
     totalIF        ≥ IF_REQ[r]
  && firstQ1       ≥ Q1_REQ[r]
  && firstQ2       ≥ Q2_REQ[r]
  && firstTop      ≥ TOP_REQ[r]
  && maxCompletedProjectTier ≥ PROJ_TIER_REQ[r]
  && (r < 8 || (recommendTickets ≥ 3 && inElectionWindow()))
```

`maxCompletedProjectTier` 记录**历史已结题项目的最高等级**（不是当前在研）。这样「主持过国家级项目」才能成为硬门槛，符合 `[研究]`「职称硬门槛是项目+论文的组合，不是纯论文数」的结论 [A]。

> ⚠️ **新玩家的第一道墙（v2 必读）**：第 1 级（副研究员）只持有 1 篇一区一作，而第 2 级（研究员）就要 **2 篇一区一作**——**一作只能靠「亲自带项目 / 抢 / 买」获得**（§2.8）。三条路一条都不走，无论全组发多少论文，都会**永久停在副研究员**（机器人实测：从不亲带的打法 0/16 通关）。新手引导文案见 §2.9 与 `docs/DEV.md` §7.4。

晋升即时收益：硕士/博士上限提升、学校年投资提升、可承接项目等级提升、同时承接上限提升、**诚信 +2**。

### 3.3 年龄与黄金年龄窗口

- 每个头衔有 `goldenAge`（见 §3.1 末列）。**在窗口内完成晋升** → 一次性奖励：

```

```

并在纪事里给一条**夸奖**文案（罕见，反差感强）。
- **超窗晋升没有任何惩罚**，只给一条嘲讽文案（例：「38 岁评上副教授，人事处的小张说：『恭喜，比隔壁王老师早了六年。』你想起王老师今年 52。」）
- **院士的年龄约束**（`[研究]` 有硬出处）：候选人须年满 **45 岁**（现实 2025 年最年轻当选者 44 岁 [A]）。

- 年龄压力并未缺失，它由三条**已生效**的机制承担：① 每级 `goldenAge` 窗口内晋升奖励（经费 += 该级校投 ×0.4、诚信 +2）；② 一局 **384 个月硬上限**（65 岁退休结局）；③ 起点 33 岁 —— 一局只有 32 年。

### 5.3 进度模型（工作量制）

**每名学生每月产出的科研进度点数**：

```
P(student) = BASE_PROGRESS(6.0)
           × abilityCoef         = student.ability / 0.5            // 0.60 – 1.90
           × happyCoef           = 0.6 + 0.004 × student.happiness  // 0.60 – 1.00
           × consumeCoef         = {挥霍 1.15, 正常 1.00, 收紧 0.85}
           × instCoef            = 1 + Σ仪器加成        // v1.3 起无封顶
           × hardPointPenalty    = 1 − 0.25 × max(未解决难点 hd)      // 0.25 – 1.00
```

**学生产出的分配**（SPEC 硬性：「每个项目至少要有一个人负责，也可以分配给多人」）：

```
玩家为每个在研项目指派学生（可多选）
每名学生最多同时负责 MAX_PROJECTS_PER_STUDENT = 3 个项目
学生分给每个项目的进度 = P(student) / 该生被指派的项目数     // 产出守恒，不是复制
项目当月进度 = Σ 指派学生的贡献 × (负责人是玩家 ? 0.85 : 1.00)
// 说明：亲带只乘「该项目」的推进速度（作用在「学生 × 该项目」这一对上），
//       不会拖慢该名学生在其**其它**项目上的贡献。
若耗材资金 = 0：项目当月进度 × 0
```

> ✅ **实现已对齐（t30 落地，t43 更新状态）**：`core/formulas.js` 的 `studentBaseProgress(student, project, ctx)` 现在接收 `ctx`，引擎每月只算一份 `projectLoadByStudent`，把学生的月产出按其在研项目数**均分**（产出守恒），与本节一致。历史：t32 曾登记「实现按（学生 × 项目）各给全额」的缺陷（当时「塞满 3 个项目 = 3 倍产出」是严格支配操作），t30 已修复并重测。**与之互补**的「多项目幸福度惩罚」（人心会累）见 §6.3 —— 守恒管产出、惩罚管人心，两件事都要在。

**进度条读数**：`项目进度 % = progress / (W × (1 + 0.10 × 难点数))`；**难点数 = 项目等级 T**（SPEC：「越难的项目进度中难点越多」）。

### 5.4 难点系统

- **难点数量 K = 项目等级 T**（T1 → 1 个，T6 → 6 个）— `[SPEC]` 硬性方向。
- 第 i 个难点在项目进度跨过 `W × i / (K+1)` 时出现（i = 1..K），当月末结算前必须处理。
- **难点难度 hd**（1–3）按项目等级抽取：

| 项目等级 T | hd 取值分布 |
|---|---|
| 1（E1, E2, N1） | hd = 1 |
| 2（E3, N2） | hd = 1（60%）/ 2（40%） |
| 3（E4, N3） | hd = 2（70%）/ 3（30%） |
| 4（N4） | hd = 2（40%）/ 3（60%） |
| 5（N5） | hd = 3 |
| 6（N6） | hd = 3 |

- **未解决难点的惩罚**：项目当月进度 × `(1 − 0.25 × hd)`，hd=1 → ×0.75，hd=2 → ×0.50，hd=3 → ×0.25。多个难点同时未解决时**取最重的一个**，不叠加（避免项目彻底冻结的死锁）。
- 结题时若仍有未解决难点：每个难点让尾款 ×0.80，且该项目论文档位整体**下调 1 档**（一区→二区→三区→四区，四区→不计入）。

#### 三种处理方式（SPEC 硬性三选一）

**① 多人攻坚**（SPEC：「影响其他项目进度」）

```
要求      参与学生 n ≥ 2（可抽调未负责本项目的学生）
耗时      1 个月
经费      3 万（协调 / 加班耗材）
代价      被抽调学生本月在【其他】项目上的产出 = 0（其他项目本月进度 −25%，按抽调比例摊）
          参与学生幸福度 −2 / 人
诚信      0
成功率    PA = clamp( 0.45 + 0.12 × n + 0.40 × (avgAbility − 0.6), 0.10, 0.95 )
          例：n=2、avg 0.60 → 0.69；n=3、avg 0.70 → 0.85；n=5、avg 0.85 → 1.00 → 截断 0.95
失败      难点保留，可下月重试；重试成功率 +0.10（累积理解加成，累计上限 +0.30）
```

**② 造假蒙混**（SPEC：「降低你的诚信值，可能会被举报」）

```
耗时      0（立即解决该难点）
经费      1 万（「润色费」）
代价      诚信 −10（每次，不可豁免）
          该难点所在项目的参与学生幸福度 −5
被查概率  PB = min( 0.10 + 0.04 × 本项目累计造假次数 + 0.02 × 全局累计造假次数, 0.60 )
被查后果  诚信 −25；该项目进度 −30%；触发「学术不端调查」事件
追加机制  全局累计造假 ≥ 3 次后，每月 15% 触发「举报审查」：
          诚信 −15、随机 1 个在研项目进度 −20%
立即坏结局 若被查时 integrity ≤ 25 → 直接进入结局「被举报」（§9）
```

**③ 单人猛干**（SPEC：「消耗更多财力，降低该研究生的幸福度」）

```
要求      指定 1 名学生
耗时      1 个月（该生本月产出全部用于攻坚，不计入任何项目进度）
经费      5 万（测试费 / 试剂加急）
代价      该生幸福度 −20
成功率    PC = clamp( 0.90 × ability − 0.11, 0.05, 0.80 )
          例：ability 0.50 → 0.34；0.70 → 0.52；0.90 → 0.70；0.95 → 0.745
失败      难点保留，该生幸福度再 −10；可下月重试，成功率 +0.10（累计上限 +0.30）
诚信      0
```

**④ 放着不管（隐含第四选项）**：接受 `1 − 0.25 × hd` 的持续减速，直到结题扣款。这是「我下个月再说」的定量代价，必须让玩家在界面上看见。

### 5.5 结题产出

论文档位用 **5 种「论文槽位模板」** 描述，每个槽位是一次加权随机：

| `PE` 登顶刊 | 0.38 | 0.40 | 0.20 | 0 | 0.02 | 7.54 |

各项目的槽位序列（`papers` 字段，直接落数据表）：

| 项目 | 槽位序列 |
|---|---|
| E1 | `[PD]` |
| E2 | `[PC, PD]` |
| E3 | `[PC, PD, PD]` |
| E4 | `[PB, PC, PD, PD]` |

结题结算流程：

1. 逐槽抽档位 → 得 IF（`JOURNAL_IF_BASE[tier] × U(0.85,1.15)`）。
2. 一作归属 = 项目负责人（§2.8）。**若负责人是学生**：该批论文的一作全归学生，玩家的台账**一篇都不加**（只计入总影响因子与课题组论文数）；玩家可在结题结算界面按篇「抢」（代价见 §2.8）。**若负责人是玩家（亲带）**：该批论文一作**全部**归玩家。
3. 尾款入账（含逾期与未解决难点扣减）。
4. 诚信：按期 +2 / 逾期 −1×逾期月数；企业项目额外 +1。
5. 参与学生幸福度 +5（结题庆祝）。
6. `maxCompletedProjectTier = max(现记录, 本项目等级)`；T6/T5 发放推荐票。

### 5.6 逾期与失败

- 超过规定时限仍可继续推进，但每月结算：尾款最终 ×0.80、诚信 −1、该项目全部学生幸福度 −2（「天天被甲方催」）。
- 逾期超过 12 个月：项目自动失败，**定金不退**、诚信 −5、该生幸福度 −10、项目从列表移除（论文与尾款全部损失）。

## 6. 学生系统

### 6.1 随机命名系统

SPEC 硬性：「需要建立一个很自然的随机命名系统，不要生成的名字千篇一律」。方案：

**字库规模**

| 库 | id | 规模 | 说明 |
|---|---|---|---|
| 单姓库 | `SURNAMES_SINGLE` | **192** | 按人口常见度分 5 档，每档带权重（王 7.2、李 7.0、张 6.9 … 末档 0.06） |
| 复姓库 | `SURNAMES_COMPOUND` | **20** | 欧阳、上官、司马、诸葛、东方、独孤、慕容、尉迟、皇甫、长孙、宇文、夏侯、西门、南宫、公孙、呼延、赫连、澹台、端木、拓跋 |
| 双字名·首字库 | `GIVEN_FIRST` | **244** | 分「偏中性 / 偏男性」两段（比例见 `src/data/names.js` 注释） |
| 双字名·末字库 | `GIVEN_LAST` | **264** | 分「偏中性 / 偏女性」两段（比例见 `src/data/names.js` 注释） |
| 单字名库 | `GIVEN_SINGLE` | **204** | 与末字库部分重叠 + 独立字（比例见 `src/data/names.js`） |
| 黑名单 | `NAME_BLOCKLIST` | **50** | 史珍香、杜子腾、朱逸群、秦寿生、范统、庞光、夏建仁 …（避免「随机出梗」的廉价感） |
| 谐音黑名单 | `HOMOPHONE_BLOCK` | **42** | 姓名连读与常见不雅词同音的拼音对 |

**组合空间** = (192 + 20) × (244 × 264 + 204) = **13,699,440**。按权重前 40% 的字覆盖 80% 生成量计算，**有效组合约 3.4×10⁵**。

> **t28 扩表完成（t37 同步）**：上表是**实际条目数**，七项全部 ≥ `NAME_DATA_TARGET`（186 / 20 / 240 / 260 / 200 / 50 / 40）；check.mjs 第 9 项已改为直读 `NAME_DATA_TARGET` 逐项比对，现在输出「[ok] 字库规模达标」，**不再有「种子规模」黄字**。实测 200 名新生：全名重复 0 例、姓氏 63 种（Top5 张 19 / 刘 17 / 王 11 / 李 11 / 陈 10）、男性 48%。扩表仍然只往数组里加条目。

**组合策略（6 步）**

1. **姓**：按权重轮盘抽；3% 概率从复姓库抽。
2. **结构**：70% 双字名 / 30% 单字名。
3. **取名**：双字名 = `GIVEN_FIRST` 抽首字 + `GIVEN_LAST` 抽末字；单字名 = `GIVEN_SINGLE` 抽 1 字。
4. **合法性检查**（最多重抽 30 次）：命中 `NAME_BLOCKLIST` 或 `HOMOPHONE_BLOCK` → 重抽；声调规则（姓与名首字同为三声）→ 重抽；与本局已出现过的名字重复 → 重抽。
5. **性别倾向**：60% 中性组合、40% 带性别倾向组合（避免「一看就是随机三字」）。
6. **用字衰减**：记录本局已用字的频次，抽字权重 × `exp(−0.35 × 已用次数)`，保证 30 名学生的用字重复率 ≤ 8%。

**效果核算**：一局约 30 名学生，生日悖论碰撞概率 = `30×29/2 / 3.2×10⁵ ≈ 0.14%`，低于 0.2% 的可接受线。

### 6.2 学生属性与科研能力分布

`[SPEC]` 硬性：幸福度初始 60、工资四档、科研能力影响进度、有在读年份与毕业进度。

| 属性 | id | 范围 | 说明 |
|---|---|---|---|
| 科研能力 | `ability` | 0.30 – 0.95 | 入学时确定，**终生不变**（天赋上限模型，借鉴 QualityCampus） |
| 幸福度 | `happiness` | 0 – 100 | 初始 60 `[SPEC]` |
| 毕业进度 | `degreeProgress` | 0 – 100 | 论文完成进度 `[SPEC]` |
| 工资档 | `wageTier` | high/mid/low/none | `[SPEC]` 四档 |
| 期望工资档 | `wageExpect` | high/mid/low | 由 ability 决定（SPEC：天赋越高越需要更高工资） |
| 心结 | `grudgeMonths` | 0 – 6 | 被抢一作后触发 |
| 延毕次数 | `deferCount` | 0–2（硕）/ 0–3（博） | |

**新生能力分布**

| 生源 | 分布 | 均值 | 区间 |
|---|---|---|---|
| 保研生（6–10 月） | `N(0.75, 0.08)` 截断 | 0.75 | [0.60, 0.95] |
| 考研生（10–12 月）主群（90%） | `N(0.53, 0.10)` 截断 | 0.53 | [0.30, 0.80] |
| 考研生·黑马（10%） | `N(0.85, 0.05)` 截断 | 0.85 | [0.70, 0.95] |

> `[研究]`：保研生整体质量高于统考生 [C]；SPEC 原话「考研生有概率刷新高科研能力的」，由 10% 黑马实现。

### 6.3 幸福度每月变化公式

```
ΔH = WAGE_DELTA[wageTier]
   + GAP_PENALTY × (expectIdx − actualIdx)
   + CONSUME_HAPPY_DELTA[耗材模式]
   + ACTION_DELTA          // 团建 / 交流课题，一次性
   + PROJECT_STRESS
   − max(0, 在研项目数 n − 1) × MULTI_PROJECT_HAPPY_PENALTY   // t42 B 方案：人心会累
   + (grudgeMonths > 0 ? −2 : 0)
   + (deferred ? −1 : 0)
   + EVENT_DELTA
   − max(0, happiness − 80) × 0.05      // 高位回归，防止幸福度无脑堆满
happiness = clamp(happiness + ΔH, 0, 100)
```

| 项 | 取值 |
|---|---|
| `WAGE_DELTA`（工资四档 `[SPEC]`） | 高 **+5** / 中 **0** / 低 **−4** / 无 **−12** |
| 档位序号 | 高 3、中 2、低 1、无 0；`GAP_PENALTY = 5`（每低一档 −5） |
| `CONSUME_HAPPY_DELTA` | 随意挥霍 **+3**（「幸福度下降变慢」`[SPEC]`）/ 正常 **0** / 收紧裤腰 **−5**（「幸福度下降加快」`[SPEC]`） |
| `PROJECT_STRESS` | 有未解决难点 **−3**；当前无负责任何项目 **−3**（「白读一年」） |
| **多项目惩罚**（t42 B 方案） | 在研项目数 **n ≥ 1** 时每月额外 **−(n−1) × `MULTI_PROJECT_HAPPY_PENALTY`（= 1）**：n=1 → **0**、n=2 → **−1**、n=3 → **−2** |
| 心结 | 被抢一作后 6 个月内每月 **−2** |

> **与 §5.3「产出守恒」的分工（两件事，别删任何一个）**：§5.3 管**产出** —— 一名学生不管挂几个项目，每月总产出恒定（被其在研项目**均分**），所以「多挂项目」变不出更多进度；本节管**人心** —— 挂的项目越多越累，每月额外扣幸福度（n=3 → −2）。两者互补：守恒堵住「堆项目刷产出」的套利，多项目惩罚让「合理分配」而不是「尽量铺满」成为最优解。**删掉任何一个，另一个立刻变成套利口子**（删惩罚 → 每人挂满 3 个项目无代价；删守恒 → 挂 3 个项目拿 3 倍产出）。另外它在两端都有压力：**n = 0** 走 `PROJECT_STRESS` 的 −3（「白读一年」），**n ≥ 2** 走本惩罚，**n = 1 是甜点**——这正是「一个人一个项目」的管理直觉。
| 延毕标记 | 延毕后每月 **−1**（永久） |

> 工资「中」档 + 正常耗材 + 无难点 → ΔH = 0，符合 SPEC「中工资不变动、正常消耗不影响幸福度」。

### 6.4 离组与极端事件（SPEC 硬性）

```
happiness 归零 → 立即离组（不掷骰，流失概率 100%），二选一形态：
    99.5%  转组：该生负责的所有项目进度 × 0.4（即 −60%）     [SPEC]
     0.5%  极端事件：该生移除，诚信 −50，项目进度归零         [SPEC]
```

**加餐事件（策划推断，不改变 SPEC 数值）**：单月幸福度下降 ≥ 25（如「抢一作 + 无工资 + 收紧裤腰」叠加）→ 触发「情绪崩溃」事件：该生当月中止产出，玩家获得一次「谈话」机会（消耗 2 精力，幸福度 +15）——把 SPEC 的「0.5% 自杀」写成了可预防的路径，避免玩家觉得是纯随机暴击。

### 6.5 毕业进度公式

```
Δdeg = DEGREE_BASE(4.0)
     × (ability / 0.5)                        // 0.60 – 1.90
     × degHappyCoef
     × consumeCoef                            // 挥霍 1.15 / 正常 1.00 / 收紧 0.85
     × projFactor                             // 有负责任何项目 1.00，否则 0.30

degHappyCoef = happiness < 30 ? 0.50 : (0.6 + 0.004 × happiness)
```

- 基准算例：ability 0.60、happiness 60、正常消耗、有项目 → Δdeg = 4.0 × 1.2 × 0.84 = **4.03 / 月** → 硕士 36 个月可攒到 145；**毕业进度不是天然瓶颈**，只有幸福度长期 **< 30** 时才真正拖慢（系数腰斩到 0.50）。
- **毕业条件**：`在读月数 ≥ 学制月数`（硕士 **36**、博士 **60** `[SPEC]`）**且** `degreeProgress ≥ 100`。
- 毕业产出：硕士 → 1 篇三区论文（IF 3.2）；博士 → 1 篇二区论文（IF 5.5）。一作归该生，玩家得通讯作者 —— **v2：该篇同样不进玩家的一作台账**（只计入总影响因子与课题组论文数）；诚信 +3。
- 玩家可在毕业结算时**抢该论文的一作**（代价同 §2.8）。

### 6.6 延毕规则（SPEC 硬性）

到期 `degreeProgress < 100` 时弹出二选一：

| 选项 | 效果 |
|---|---|
| **延毕 1 年** | `在读月数 −= 12`；幸福度 **−40**（一次性，`[SPEC]`「大幅降低幸福度」）；此后每月 −1；**不占用招生名额** `[SPEC]` → 立即释放 1 个招生名额；`deferCount += 1` |
| **放弃（肄业）** | 该生离组，负责项目进度 ×0.4，诚信 −2 |

- 延毕上限：硕士 **2** 次、博士 **3** 次；超限强制肄业。
- 延毕生仍计入「在读学生数」且消耗工资，但**不占用名额**——这是 SPEC 明写的「多招一个学生」的来源。

### 6.7 工资

| 学位 | 高 | 中 | 低 | 无 |
|---|---|---|---|---|
| 硕士（万/月） | 0.30 | 0.15 | 0.05 | 0 |
| 博士（万/月） | 0.60 | 0.30 | 0.10 | 0 |

## 8. 行动系统

`[SPEC]` 硬性：4 种行动。精力在月初重置，行动消耗精力、不消耗月份。

| # | 行动 | 精力 | 经费 | 效果 | 每月限次 |
|---|---|---|---|---|---|
| 1 | **与学生交流课题** | 2 | 0 | 指定 1 名学生 + 其负责的 1 个项目：该项目进度 **+8 点**（直接加，不受难度/仪器系数影响）；该生幸福度 **+4**、毕业进度 **+2** | 每名学生 2 次（实现真值：`src/core/engine.js` 的 `TALK_PER_STUDENT_PER_MONTH = 2`；`src/data/actions.js` 的 `limitPerMonth: 'perStudent'` 表示「按人计数」；UI 显示的数字取自 `vm.consts.limits.talkPerStudentPerMonth`，不再写死文案） |
| 2 | **开组会** | 4 | 0.5 万 | 全体在读学生负责的**所有**项目各 **+3 点**；全体学生幸福度 **+2** | 不限次，但同月第 2 次效果 ×0.5、第 3 次 ×0.25、第 4 次起无效 |
| 3 | **锻炼与享乐** | 3 | 2 万 | 健康 **+8**（健康 ≥ 90 时改为 +3，边际递减） | 不限次 |
| 4 | **去团建** | 5 | 1.0 万 × 在读学生数 | 全体在读学生幸福度 **+8** | 1 次/月 |

- 量化对价（以 rank1、2 名学生、18 点/月总产出为基准）：「交流课题」2 精力换 8 点进度 ≈ 0.44 个学生月；「开组会」4 精力换 `3 × 在研项目数` 点，在研 3 个项目时 ≈ 9 点，效率约 1.5 倍，但不受「指定对象」控制。
- 精力不足时行动按钮置灰；本月剩余精力在「下一个月」作废（`ENERGY_CARRYOVER = 0`）。

## 10. 幽默基调与随机事件

### 10.1 文案风格三条原则

1. **反差优先**：用官方的、严肃的、制度化的语言包装荒诞的机制。例：把「拼图蒙混过关」写成「图像组学规范化处理」；把「抢一作」写成「导师对论文贡献度的再评估」。
2. **不做道德说教**：负面选项必须**有利可图且代价明确**（`[研究]`：同类作品实测显示玩家拥有权力后大多选择做好导师，因此坏选项应「有利可图但不是被系统劝阻」）。系统永远不骂玩家。
3. **具体到物件与数字**：不写「很累」，写「-80℃ 冰箱跳闸一夜」；不写「学生不满」，写「离心管洗了三遍，第四遍他摔了」。真实道具：离心机、离心管、-80℃ 冰箱、抗体、APC、审稿人二号、基金号、结题决算说明书。

### 10.2 随机事件机制

- 每月结算时抽取 **1–2 条**随机事件；每条在纪事（流水账）里留一句文案。
- 三类气质：**倒霉事**（仪器罢工、样品没了）、**荒诞事**（组会跑题、学生恋爱）、**体制事**（破四唯文件、基金委来函、同龄人的帽子）。
- 事件池实现参考 phd-game 的「条件 + 动作 + 效果」DSL：`{ id, weight, cond(state), effects[], text }`，全部放 `src/data/events.js`。
- 所有文案**不写玩家的内心活动**，只写发生了什么和一句旁观者的话——把解释权留给玩家。

## 11. 数值自检（平衡验证）

用一份**一次性**的启发式策略脚本（不入交付物，不写进 `src/`）跑 16 局，"体面但非最优"的玩家策略（按 IF/工作量 选项目、按门槛顺序买仪器、招满约 80% 名额、中档工资），结果：

| 指标 | 结果 |
|---|---|
| 完成通关 | 15 / 16 局（1 局因资金链断裂失败） |
| 通关月中位 | **182 个月** |
| 通关月区间 | 171 – 189 个月 |
| 末局总 IF | 1403 – 1471（门槛 1400，压线通过） |
| 一区一作（v1 口径，已过期） | 22 – 32 篇（v1 里学生一作也算老板的，所以数字虚高；v2 只认玩家本人一作，来源见 §2.9） |
| 结题项目数 | 44 – 50 个 |
| 逾期结题 | 3 – 7 个 / 局（约 10%，构成稳定压力但不致命） |
| 末局诚信 | 61 – 89（抢一作与造假是真代价，但没到翻车） |
| 最低资金余额 | −103 至 +21 万（多次触底 → 经济压力真实存在） |

关键平衡结论：

1. **总 IF 门槛 1400 是终局瓶颈**（v1 脚本末局 1403–1471 压线）；**一作门槛是中期瓶颈，v2 后主要靠「亲自带项目」补齐**（抢 / 买是补位手段）——原句「必须靠抢或买」已过期，见下方 v2 更新。
2. **国家项目之间没有支配性选择**：IF/工作量的比值集中在 0.077–0.105。
3. **企业项目是「现金流」而非「学术」**：IF/万为 0.092–0.305，而国家项目为 0.177–0.505；企业项目定金率 0.40、时限短，是前期买仪器的钱袋子。
4. **越级承接会被时限杀死**：rank1 硬接 N2 面上（有效工作量 ≈ W×1.20 = 360）需约 16 个月，逼近 18 个月时限；接 N3 必然逾期。规则本身完成了难度分层，不需要额外「禁止」。
> **v2 更新（t32）**：上表是**一份未留档的一次性启发式脚本**在 v1 口径下的锚点，其中「一区一作 22–32 篇（靠抢/买补缺口）」与「总 IF 1400 是终局瓶颈、一区/正刊是中期瓶颈」两处表述已过期：
> 1. v2 后一作门槛只认**玩家本人**的一作，主要来源是**亲自带项目**（§2.8、§2.9），抢 / 买是补位手段；
> 2. t24 实测通关率（8 局）：速通 6/8、随手玩 11/16、**从不亲带的打法 0/16（卡死在 rank1）**；总 IF 门槛依旧是终局瓶颈，但**一作门槛才是新玩家的第一道墙**；
> 3. t13 已裁定新口径下的门槛与项目经济性（BALANCE §18.10/§18.3：二区门槛下调、杰青+长江的正刊要求 2→1、项目要求改成「一次旗舰 + 两次重点」、N5/N6 效率与耗材调整），等待 t30 落表后本节与本文件 §3.1 一起用实测替换。
